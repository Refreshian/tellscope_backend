# KFC: тональность месячных итогов — полный счёт по всему корпусу месяца

Датасет: индекс **1102**, `kfc_13.05.2024-22.09.2026` (2 957 349 сообщений, период
13.05.2024 19:17 — 08.09.2026 22:45 МСК по `timeCreate`).

## Что было не так

В месяцах, посчитанных **до** исправления периода, поле `messages.in_slice` содержало размер
**среза чтения** (4…322 сообщения, доля негатива 100 %), а не объём всего месяца. Значения
попадали и в `tonality` (у 17 из 28 месяцев это 4…322 сообщения со 100 % негатива), поэтому
месячные итоги были несопоставимы между собой, а в годовых отчётах приходилось держать
оговорку «доля негатива в месячных итогах завышена (срез чтения)».

## Как посчитано

Тональность пересчитана **полным счётом по всему корпусу месяца, без модели**, механизмом
запросов самого проекта (`agent_engine.tools_data`):

* `_query(None, lo, hi, tone)` → `bool.filter`: `{"range": {"timeCreate": {"gte": lo, "lte": hi}}}`
  и `{"term": {"toneMark": -1 | 0 | 1}}` (поля тональности: −1 негатив, 0 нейтрал, 1 позитив);
* `_exact_count(index_name, query)` → точное число документов (`_count`, не `size`);
* `_terms(index_name, "hub", 8, query)` → площадки месяца;
* границы месяца — `agent_engine.context.to_unix_start("ГГГГ-ММ-01")` и
  `to_unix_end("ГГГГ-ММ-<последний день>")`: сутки по МСК (UTC+3) включительно.

Итог по месяцам сверен с прямой агрегацией по году (`2024-05-01…2024-12-31` и т. д.) — совпадает
до сообщения. Скрипт пересчёта не импортирует `main`: подпакет `agent_engine` подгружается
минуя `agent_engine/__init__.py`, а ES-клиент подставляется в `tools_data` через подмену `_m().es`
(поэтому CUDA-процессы прода не затрагиваются).

```
2024 (май–декабрь): 65 317 / 698 950   = 9,35 %
2025 (12 месяцев):  153 506 / 1 276 635 = 12,02 %
2026 (январь–август): 86 853 / 952 028  = 9,12 %
всего 28 месяцев:   305 676 / 2 927 613 = 10,44 %
```

(2 957 349 − 2 927 613 = 29 736 сообщений — 01.09.2026…08.09.2026, они вне месячных итогов
периода.)

## Что обновлено

28 месячных итогов `data/1/reports_directory/kfc_13.05.2024-22.09.2026 Отчёты/<ГГГГ-ММ>_summary.json`:

* `messages.total` / `negative` / `neutral` / `positive` и `negative_share` (проценты,
  `share_unit: percent`) — полные цифры месяца;
* `messages.in_slice` = полный объём месяца (как и раньше, «весь срез периода»);
* `messages.read_slice_legacy` — прежнее значение среза чтения (история сохранена);
* `messages.count_source` / `count_from` / `count_to` / `count_ts_*` — метод и границы счёта;
* `tonality.{negative,neutral,positive,total,shares,source,scope}` — полный счёт;
* `tone_recount.previous` — прежние цифры, `notes` — правка формулировок;
* `period.from/to/from_ts/to_ts` заполнены границами месяца.

Бэкапы прежних итогов: `/home/dev/tellscope_app/backups/kfc_tone_<ГГГГММДД_ЧЧММСС>/`.

Месячные DOCX/PDF **не пересобирались**: тональность в них не выводится из полей
`messages.*`/`tonality` (это текст модели, а доли тем считаются от полного корпуса месяца —
например, «3 369 сообщ., 4,0 % среза» при 84 994 сообщениях за февраль 2025 совпадает с полным
счётом).

## Годовые и межгодовой отчёты

Собраны `kfc_build_annual.py` (данные — инструментом `read_reports` из обновлённых месячных
итогов, документы — сборщиками платформы `agent_engine.tools_reports._build_docx` / `_build_pdf`):

```
kfc_build_annual.py --apply      # 4 отчёта в «Годовые» и 4 в «Годовые Агент»
kfc_build_annual.py              # сухой прогон: сверка месячных итогов с агрегацией ES
```

Оговорка про срез чтения убрана; в отчётах явно указано, что объём и тональность по месяцам —
полный счёт по всему корпусу каждого месяца. Прежние версии отчётов сохранены в подпапках
`_архив_до_полного_счёта_<ГГГГММДД_ЧЧММ>` внутри папок «Годовые» и «Годовые Агент».

Проверка: сумма 28 месячных итогов == годовые агрегации == прямая агрегация ES
(65 317/698 950, 153 506/1 276 635, 86 853/952 028; всего 305 676 из 2 927 613), итоги читаются
инструментом `read_reports`, в новых отчётах нет формулировок «срез чтения» / «250–320».
